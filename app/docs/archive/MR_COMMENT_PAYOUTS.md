# Current product: reply on the merged MR

This supersedes contributor login/inbox, email claim links, Discord and prior payout-period flows.

The system evaluates an actual merged MR, reserves an eligible affordable single-author reward, then posts a bot comment tagging its creator. The author replies in normal language with one receiving wallet address. Backend re-fetches and verifies the merge and reply directly from GitHub, binds one recipient and automatically submits the payout. No source-control OAuth login is required from the contributor, because the platform-authenticated comment is the author authorization.

GitHub adapter: `POST /api/comments/github` takes only provider/repository/repositoryId/prNumber/commentId, authenticated with the source integration secret. The source Actions workflow uses issue_comment:created for PR conversation comments, with no checkout or comment execution. Public arbitrary comments cannot supply an amount, reward ID, signer, network or claim payload. Verification uses immutable numeric IDs, exact repository/PR/SHA, original comment ownership/conversation, creation after merge+bot prompt, and no edits. One distinct valid nonzero checksummed-or-lowercase address is extracted from text; multiple addresses are ambiguous and ignored. The first accepted destination is locked.

Automatic reservation/payout runs in the trusted central worker path using the backend's separate funded Arc signer. Failed dispatches keep recipient state for a retry. Sender transactions are recorded while pending; paid state requires matching canonical RewardClaimed event with two successor blocks. Chain mapping and claim ID enforce exactly one payment. Prompt markers plus per-reward leases recover posted comments without routinely duplicating them. A failed transfer does not mark the MR paid. Comment processing has no wallet-bearing shell interpolation and never runs contributed content.

Configure GITHUB_COMMENT_TOKEN as a repo-scoped bot-account fine-grained PAT with PR/issue comment write permission on the backend. Source repo receives only its API URL and trigger secret. Central worker needs its existing worker/read/0G configuration; backend signer needs testnet gas for both reservation and payout. Apply all migrations through 012. Current actual source-control adapter is GitHub; GitLab integration is not claimed. The provider boundary can be extended using the same verified-author/comment model.

The comment publicly associates the author and destination wallet. Source-control history and Arc history remain public; no application-level contributor profile, rewards search or history feed is created. Only minimal anti-replay/payment records remain after data minimization. No real prompt, comment, payout, deployment or CRE simulation has occurred during implementation. Credentials-required live gates remain BLOCKED. No tests were added/run under the user's explicit instruction.
